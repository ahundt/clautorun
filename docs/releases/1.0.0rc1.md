# autorun v1.0.0rc1

Date: 2026-08-20

## Upgrade notes

Existing `/ar` command spellings and task state remain compatible with v0.12.0;
this RC requires no state migration command.

The optional PDF dependency sets changed:

- The `cpu` extra now installs `pypdf`. The CLI backend id remains `pypdf2`, so
  existing `--backends pypdf2` commands still work.
- The `gpu` extra installs docling on Linux and Windows. It installs no backend
  on macOS while docling's model stack pins an advisory-affected transformers
  4.x release.
- The `marker` backend remains discoverable for separately managed installs,
  but no published extra installs marker-pdf while it pins Pillow below the
  first fully patched release.

## User-visible changes

- Pi installs an owned extension with in-process tool vetoes, display-only
  commands, attributed continuation, compaction-aware transcripts, and
  daemon-backed `TaskCreate`, `TaskUpdate`, `TaskList`, and `TaskGet` tools;
  `TaskUpdate` also accepts an atomic `taskUpdates` array.
- OpenCode's native todo list (`todo.updated`) is mirrored into autorun's task
  status; the plugin still has no stop event, so it does not gate completion.
- Pi task acknowledgments report Python-confirmed state. Task ids are the
  session's sequential integers minted by the daemon (Claude Code's shape),
  and lists follow creation order. Dependency-ready work appears before
  blocked tasks and bounded terminal history.
- Prime Agent (PrimeIntellect's build of the Pi coding agent) installs the
  same extension under `~/.prime/agent/extensions/ar/` with its own
  `cliType: "prime"` identity; `autorun --install --prime` selects it alone.
- Scope durations accept day units (`2d`, `1d12h`) in `/ar:ok`,
  `/ar:globalok`, `/ar:cache`, and `/ar:task pause`; a zero count is
  rejected instead of granting a never-active allow.
- A user-authored skill in `~/.agents/skills` no longer gains a same-named
  native copy on harnesses that read both routes; the withheld copy is
  reported as a preserved conflict and stale duplicates retire on reinstall.
- Every shipped skill wraps its major sections in balanced semantic XML
  regions; `ai-skill-builder` 1.3.0 states the rule (SKILL-REQ004), its
  audit script fails a body without regions, and it absorbs the standalone
  `engineer-agent-skills` package.
- `autorun` publishes to PyPI through TestPyPI-first OIDC trusted publishing. It
  is the only distribution: PDF extraction ships inside it as `autorun[pdf]`, so
  a plain install pulls no extraction dependency at all.
- Concurrent hook state uses JSON or SQLite storage with migration and rollback
  receipts. Cross-process tests cover reminder claims, task writes, Stop
  enforcement, and session isolation.
- Install and uninstall ownership covers the supported harness routes without
  replacing user-authored files.
- Settings resolve CLI parameter > environment variable > config file > default.
  A dict-valued setting written to the config file is merged onto its default,
  so naming one entry adds or retunes that entry instead of discarding the rest
  — omission means "no opinion", never "delete". This matters most for
  `default_integrations`, the safety-guard table, where substitution would have
  removed every guard the file did not mention.
- A daemon restart no longer makes Pi, Prime or OpenCode block every command.
  The shared bridge treats an empty hook response as "no decision", which is how
  the hook protocol spells an allow, instead of a malfunction to deny on.
- An install against an unresponsive harness CLI costs one timeout rather than
  one per command, and names the commands it skipped.

## RC installation

```bash
claude plugin marketplace add https://github.com/ahundt/autorun.git
claude plugin install ar@autorun
```

Optional Claude companion:

```bash
claude plugin install pdf-extractor@autorun
```

Python tools:

Pin the version. `uv tool install autorun` does not select a prerelease, so
without the pin it installs nothing today and the wrong thing once a stable
release exists — while appearing to have installed this candidate.

```bash
uv tool install 'autorun==1.0.0rc1'

# With the PDF extraction backends:
uv tool install --force 'autorun[pdf]==1.0.0rc1'

# Confirm which version answered:
autorun --version    # expect 1.0.0rc1
```

For source installations, see the repository README. Existing large or busy
JSON-state installations can inspect the configured backend while their scoped
daemon is stopped:

```bash
autorun --state-status
autorun --state-migrate
autorun --state-status
```

Rollback remains available with `autorun --state-rollback`.

## Verification

The release gate covers Python 3.10 through 3.14 on Ubuntu, Python 3.13 on macOS
and Windows, coverage, release artifacts, tmux integration, state benchmarks,
TestPyPI installation, and scratch-home marketplace installation. Paid model
calls and retired Gemini model calls remain opt-in.

[Compare v0.11.0 with v1.0.0rc1](https://github.com/ahundt/autorun/compare/v0.11.0...v1.0.0rc1)

`v0.11.0` is the base because it is the newest tag that exists on GitHub.
`0.12.0` has a changelog entry but was never tagged publicly, so a comparison
from it returns 404 for everyone who is not the maintainer.
